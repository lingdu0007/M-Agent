# 领域文档

本仓库采用 single-context 布局。

## 探索代码前

- 如果根目录存在 `CONTEXT.md`，先读取该文件。
- 读取 `docs/adr/` 下与当前工作区域相关的架构决策。
- 如果这些文件不存在，直接继续，不要报告缺失，也不要提前建议创建。`/domain-modeling` 会在术语或决策得到确认时按需创建它们。

## 文件布局

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

## 使用领域词汇

当输出中需要命名领域概念时，使用 `CONTEXT.md` 中定义的术语，不要为已有概念引入其他同义词。

如果所需概念尚未出现在词汇表中，应重新判断它是否属于本项目领域；如果确实存在缺口，将其记录下来并交由 `/domain-modeling` 处理。

## 标记与 ADR 的冲突

如果拟议工作与现有 ADR 冲突，应明确指出冲突，而不是静默覆盖已有决策。
